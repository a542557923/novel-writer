# 酒馆预设（SillyTavern Preset）兼容功能实现计划

## Context

用户希望 ai-novel 直接兼容 SillyTavern 酒馆预设（以 Kemini_Dramatron_v3.1.json 为样本，493KB）。ST 预设格式已解析确认：

- `prompts[]`：{identifier, name, role, content, marker, enabled, injection_position(0相对/1绝对), injection_depth}
- `prompt_order[0].order[]`：真实顺序以此为准，其 enabled 覆盖 prompts 内的
- 标准 marker 标识符：worldInfoBefore / worldInfoAfter / personaDescription / charDescription / charPersonality / scenario / dialogueExamples / chatHistory / agentSystemPrompt(main) / agentTask / agentResults / nsfw / jailbreak
- 宏系统：`{{setvar::名::内容}}`（按顺序生效）、`{{getvar::名}}`、`{{trim}}`、`{{//注释}}`、`{{char}}`、`{{user}}`
- Kemini 特点：风格开关用 setvar 填变量、模板用 getvar 展开；末尾有启用的 assistant prefill 消息；ICOT 模式让模型输出 `<Interleaving>` + `<thinking>` 交错格式

**用户已确认：采用全局预设库**（多预设集中管理，每本书选用其一）。

## 核心设计

### 数据与存储

- **全局预设库**：`data/presets/<id>.json`，与 projects 平行的独立目录。store 启动时全量加载进内存 Map
- **项目绑定**（走现有 settings 合并机制）：`settings.presetId`（空 = 不使用预设，走原有组装）、`settings.presetCharName`、`settings.presetUserName`（{{char}}/{{user}} 的本书映射，per-book 因为每本书主角不同）
- **预设对象 schema**（全局）：
  ```
  { id, name, importedAt,
    cleanOutput: true,          // 生成输出剥离 thinking/Interleaving 标签
    prompts: [{ identifier, name, role('system'|'user'|'assistant'), content(原文不预展开),
                marker(bool，仅按标准标识符判定), enabled,
                injection_position(0|1), injection_depth(默认4) }] }  // 已按 prompt_order 排序
  ```
- 解析时字段白名单裁剪（丢 system_prompt/forbid_overrides 等），缩小落盘体积
- 预设删除后，引用它的项目 settings.presetId 悬空 → getPreset 返回 null → 自动回落原有组装（优雅降级）

### marker 映射（本项目数据 → ST 占位符）

| ST marker | 数据源 |
|---|---|
| worldInfoBefore / worldInfoAfter | 世界书触发条目（position before/after），用 formatSection 包装 |
| charDescription | pinned 世界书条目（pinned = ST 角色卡，现有设计决策） |
| scenario | settings.storyBible（本书大纲） |
| agentSystemPrompt / main | settings.systemPrompt（空则注入空，不回退默认——预设即完全接管） |
| chatHistory | 正文上下文（buildContextText + injectAuthorNote） |
| agentTask | 模式指令（continue/expand/polish/custom + instruction） |
| personaDescription / charPersonality / dialogueExamples / agentResults / nsfw / jailbreak | 空字符串 |

marker 未启用 → 对应数据不注入（ST 语义）。作者注/contextChars/scanChars 等设置继续作为数据源参数生效——预设改变的是组装方式，不废掉 settings。

### 模块拆分（避免循环依赖，全部单向）

```
context.js（新，纯函数）← prompt.js、preset.js 都只依赖它
prompt.js（原有路径）← routes.js
preset.js（新）← routes.js、store.js
store.js ← routes.js（store requires preset 做 load 时 normalize）
```

从 prompt.js 原样提取到 `server/context.js`（零行为变更，buildPrompt 改为调用）：`buildContextText`（现 95-111 行 expand/polish 片段逻辑）、`scanWorldbook`（现 113-120 行）、`formatSection/formatEntry/TYPE_LABEL`、`injectAuthorNote`、`MODE_INSTRUCTION`。prompt.js 保留 buildPrompt 与 DEFAULT_SYSTEM_PROMPT，并 re-export 兼容现有引用。

## 文件改动清单

### 1. `server/context.js`（新建，~90 行）

从 prompt.js 提取的共享函数（见上），签名为纯函数：`buildContextText({project, chapter, mode, selection}) → {contextText, selectionBlock}`、`scanWorldbook(project, contextText) → {enabled, pinned, wiBefore, wiAfter, scanWindow}`。

### 2. `server/prompt.js`（改）

- 删除被提取的函数体，改为 `const ctx = require('./context')` 调用；对外 re-export 不变
- buildPrompt 逻辑不动（预设分流放在 routes.js，见下）

### 3. `server/preset.js`（新建，核心 ~300 行）

- `parsePreset(raw)` → 规范化 schema。校验：`!Array.isArray(raw?.prompts)` 抛「不是有效的 SillyTavern 预设（缺少 prompts 数组）」。prompt_order 缺失时 fallback 用 prompts 原始顺序；order 引用了不存在的标准 marker → 合成空占位条目；非标准 identifier 缺失 → 跳过；role 非法归一 system
- `normalizePreset(saved)` → store.load 兼容补全字段
- **宏引擎**：
  - `scanMacros(text)`：深度计数扫描器（处理嵌套 `{{setvar::x::a {{getvar::y}} b}}`），未闭合 `{{` 视为纯文本
  - `expandContent(content, vars, {charName, userName}, depthGuard)`：按 inner 前缀分派——`//`注释删除；`trim` 删除并置 trimSeen；`char`/`user` 替换名字；`getvar::名` → vars[名] ?? ''；`setvar::名::内容` → 值部分递归展开（深度上限 8）后记入 vars 并从文本移除；未知宏原样保留。trimSeen 时删除本条内所有空白行
  - vars 由 buildPresetMessages 创建、按 order 顺序共享传递：条目 A 的 setvar 对后续条目生效；**禁用条目的 setvar 不执行**（ST 语义）
  - 宏只在预设 prompt 的 content 内展开；世界书/正文/storyBible 数据源里的 `{{` 原样保留（防注入）
- `buildPresetMessages({preset, project, chapter, mode, selection, instruction})` → 返回与 buildPrompt 同构 `{messages, usedEntries, stats}`：
  - 计算 marker 数据表 M（映射见上表，复用 context.js）
  - 按 preset.prompts 顺序遍历：marker → 注入 M[identifier]（不展开宏）；普通条目 → expandContent；空内容跳过
  - injection_position=1 的条目收集为 absolutes，组装完后按 depth 降序 splice 插入（同 depth 保持出现顺序；插入基准排除末尾 assistant prefill；depth 越界 clamp 0）
  - usedEntries 格式与现有完全一致（PreviewPanel 零适配）；stats 增加 `{preset: true, presetName, messageCount, activeMarkers}`
  - messages 为空时抛「预设组装结果为空」
- `createOutputFilter()` → 流式标签过滤状态机 `{push(chunk)→string, end()→string}`：
  - 标签（大小写不敏感）：`<thinking>`/`</thinking>` 为块标签（中间内容丢弃）；`<interleaving>`/`</interleaving>` 删标签保内容；normal 态也识别孤儿 `</thinking>` 直接删
  - **尾部悬挂处理**：chunk 末尾出现标签真前缀（如 `<thi`）时滞留 pending，下个 chunk 到来后要么补全成标签吞掉、要么证实是普通文本放行——保证任意 chunk 划分下输出一致
  - end()：thinking 态丢弃 pending；normal 态返回残段

### 4. `server/store.js`（改）

- `load()`：读取 `data/presets/*.json`（ensureDirs 同时建 presets 目录），normalizePreset 后入 Map；项目 load 不变（presetId 在 settings 合并里，DEFAULT_SETTINGS 增补 presetId/presetCharName/presetUserName 空值默认）
- 新增：`listPresets()`（摘要：id/name/promptCount/updatedAt）、`getPreset(id)`、`createPreset(raw)`（parsePreset + uid + 立即落盘）、`updatePreset(id, patch)`（name/cleanOutput 直接 assign；prompts 按 identifier 匹配部分合并 enabled/content；立即落盘）、`deletePreset(id)`
- require('./preset') 单向依赖，无循环

### 5. `server/routes.js`（改）

- 新增预设端点：`GET /presets`、`POST /presets`（body=ST 原始 JSON）、`PUT /presets/:pid`、`DELETE /presets/:pid`
- **组装分流**（preview 与 generate 两处，同样 3 行）：`const presetObj = p.settings.presetId ? store.getPreset(p.settings.presetId) : null` → `presetObj ? buildPresetMessages({...参数, preset: presetObj, charName: p.settings.presetCharName, userName: p.settings.presetUserName}) : buildPrompt({...})`
- generate SSE 接入输出过滤（仅预设启用 cleanOutput 时）：
  ```
  const filter = presetObj && presetObj.cleanOutput !== false ? createOutputFilter() : null
  let cleaned = ''
  onChunk: c => { const out = filter ? filter.push(c) : c; if (out) { if (filter) cleaned += out; send('chunk', {text: out}) } }
  chatStream 完成后: filter && filter.end() 的尾巴补发
  send('done', { text: filter ? cleaned : text, stats })   // cleaned 为唯一真源，与流一致
  ```
  autoExtract 的 extract 输入也用清理后文本（thinking 不进实体抽取）；无预设路径逐字节不变

### 6. `web/src/api.js`（改）

新增：`listPresets: () => fetch('/api/presets').then(j)`、`importPreset: (raw) => post('/api/presets', raw)`、`updatePreset: (pid, patch) => PUT`、`deletePreset: (pid) => DELETE`。streamGenerate/Editor 零改动（清理在服务端完成）。

### 7. `web/src/components/PresetPanel.jsx`（新建，对齐 WorldBook 模式）

Props `{ project, onPatch, toast }`。结构：

- **本书绑定区**：select「本书使用的预设：不使用 / 各预设」（保存 settings.presetId，走现有 updateProject settings 流程）；选中后显示 `{{char}}/{{user}}` 名字两个 input（blur 保存 settings.presetCharName/presetUserName）；启用时提示条：采样参数不随预设导入请到设置配置；main=系统提示词、scenario=大纲 的数据源说明
- **预设库区**：「导入预设」file input（FileReader→JSON.parse→api.importPreset→刷新列表）；预设卡片列表（名称/条数/导入时间），操作：展开编辑 prompt 条目、删除（confirm，提示影响所有引用它的书）
- **条目编辑**（展开某预设）：按存储顺序列表，每条：checkbox 开关（乐观更新 PUT prompts:[{identifier,enabled}]）+ 名称 + role 徽标 + 字符数 + marker 中文徽标（chatHistory→正文、main→主指令、worldInfoBefore/After→世界书前后、charDescription→常驻角色、scenario→大纲、agentTask→指令…）+ `@深度N` 绝对注入徽标；点击展开 PromptEditor（textarea + 保存/重置，对齐 EntryEditor 模式）；marker 条目不提供 content 编辑，显示一行灰字说明数据来源。提示：条目开关为全局（影响所有选用此预设的书）
- CSS 在 styles.css 追加少量类，复用现有 `.wb-toolbar/.chip/.btn/.entry-editor` 体系

### 8. `web/src/App.jsx`（改）

tabs 数组加 `['preset', '预设']`（世界书之后），渲染 `<PresetPanel project onPatch={patchProject} toast />`。

### 9. `web/src/components/PreviewPanel.jsx`（改）

- messages 渲染通用化：`data.messages.map` → `<details><summary>{role中文} · 第N条 · X字（末条 assistant 标 prefill）</summary><pre>` （去掉写死的 ①②System/User 文案）
- stats 区：preset 模式显示 `预设「名」· N 条消息`；PromptOrderHint 在 preset 模式换文案「组装顺序：按预设 prompt_order（含宏展开与绝对注入）」

### 10. `web/src/components/SettingsPanel.jsx`（改）

project 启用预设时，表单顶部提示条：系统提示词将作为预设 main 占位符数据源（留空不注入、不回退默认）；大纲注入 scenario；作者注仍随正文生效。

## 关键边界

- **CommonJS 无循环**：context.js ← prompt.js / preset.js；store.js → preset.js；routes.js 汇总分流。全部单向
- **setvar 顺序语义**：共享 vars 按 order 传递；禁用条目 setvar 不执行；空内容 getvar 替换为空串
- **done 一致性**：服务端 cleaned 累积是唯一真源（不二次过滤 chatStream 返回值）；abort 时 Editor 已收流兜底
- **prefill 兼容**：末条 assistant 在严格网关可能报错——用户可在面板禁用该条目（逃生门）
- **采样参数不导入**：温度等仍用全局 config（用户手动调；Kemini 长文输出记得把 maxTokens 调大）
- 5mb body 限制覆盖 500KB 预设导入

## 验证（Kemini 完整链路）

1. 导入 Kemini_Dramatron_v3.1.json → 列表 50 条按 order 排列、marker 徽标正确、assistant prefill 在末尾
2. 未绑定预设刷新预览 → 旧双消息结构（回归）
3. 绑定预设 → 预览：消息数 = 启用条目数；全文搜 `{{` 零残留；末条 assistant prefill；worldInfoBefore 处有触发条目；填 presetCharName 后相应变化
4. 宏开关：禁用某风格 setvar 条目 → 再预览，getvar 模板内容变化（验证禁用即失效）
5. 禁用 chatHistory marker → 预览无正文；恢复
6. 生成（开 ICOT 条目）→ 编辑器流式文本无 `<thinking>`/`<Interleaving>` 泄漏（含多交错块、标签跨 chunk 接缝），done 后正文干净
7. 临时关 cleanOutput 确认原始输出带标签（证明过滤在工作）；抽取结果无 thinking 残留
8. 生成中途停止 → 保留已生成部分无半截标签
9. 删除预设 → 引用项目自动回落原组装；旧项目数据（无 presetId）正常
